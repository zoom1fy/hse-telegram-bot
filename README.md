# HSE Schedule Bot

Telegram-бот с расписанием группы **ВПИ 26** (HSE Нижний Новгород). Парсит Google-таблицу и показывает ближайшие занятия.

## Запуск (Docker)

```bash
cp .env.example .env      # вписать BOT_TOKEN
docker compose up -d --build
```

## Запуск (локально)

```bash
npm install
npm run build
BOT_TOKEN=... npm start
```

Для разработки: `npm run dev`.

## Переменные окружения

| Переменная    | Обязательно | По умолчанию |
|---------------|-------------|--------------|
| `BOT_TOKEN`   | да          | —            |
| `SHEET_ID`    | нет         | таблица ВПИ 26 |
| `SHEET_GID`   | нет         | `263198462`  |
| `STORE_PATH`  | нет         | `subscribers.json` |
| `TELEGRAM_API_ROOT` | нет   | `https://api.telegram.org` (можно указать Bot API proxy) |
| `TELEGRAM_PROXY` | нет     | — (HTTP/HTTPS или SOCKS5-прокси для Telegram API) |

## Как работает

- При старте и каждые 2 часа (06:00–22:00 МСК) бот скачивает таблицу как CSV и перепарсивает.
- Если расписание изменилось — подписчики получают уведомление.
- Подписки хранятся в `subscribers.json` (в Docker — в `./data`).
- При сетевых сбоях (ECONNRESET и т. п.) бот не падает: загрузка расписания и запуск
  Telegram-клиента повторяются с увеличивающейся паузой.

## Календарь (Apple / Google)

В карточке дня (из `/menu`) и в `/today`, `/tomorrow` есть кнопка **«📆 Добавить в календарь»**.
Нажатие не создаёт лишних сообщений: карточка дня убирается, а на её месте появляется
`.ics`-файл с кнопкой **«◀️ Назад к расписанию»**, которая возвращает карточку дня.
Повторные нажатия не засоряют чат — файл всегда один.

Так устроено потому, что Telegram не позволяет «прикрепить» файл к уже существующему
текстовому сообщению: бот удаляет карточку и отправляет файл на её место.

Дальше просто открой файл и выбери «Добавить в календарь»:
iPhone/Mac (Apple Календарь), Google Календарь и другие календари поддерживают `.ics`.
Если iPhone не предлагает добавить из превью — «Поделиться» → «Сохранить в Файлы»,
затем открой файл из «Файлов».

В событиях есть название, аудитория, преподаватель, ссылка (для онлайн-пар) и
напоминание за 15 минут. Сдвоенные пары (два подряд идущих занятия с одинаковым
предметом/преподавателем/аудиторией) склеиваются в одно событие, чтобы в календаре
не было двух карточек подряд.

## Команды

- `/start` — меню
- `/menu` — ближайшие занятия по датам
- `/today`, `/tomorrow` — сегодня / завтра
- `/week` — текущая неделя
- `/notifications` — включить/выключить уведомления
- `/subscribe`, `/unsubscribe` — то же командами

## Если бот не отвечает

- `429: Too Many Requests: retry after N` — Telegram временно ограничил запросы.
  Бот сам подождёт указанное время и переподключится; не перезапускай контейнер в цикле,
  частые рестарты только продлевают блокировку.
- `socket hang up`, `getMe: таймаут 30 с`, `fetch failed` — сеть сервера нестабильно
  достаёт `api.telegram.org`. Проверь из контейнера:

  ```bash
  docker compose exec bot node -e "fetch('https://api.telegram.org/bot'+process.env.BOT_TOKEN+'/getMe',{signal:AbortSignal.timeout(15000)}).then(async r=>console.log(r.status,await r.text())).catch(e=>console.error(e.name,e.message))"
  ```

  Если запрос висит или рвётся — нужен прокси: задай `TELEGRAM_PROXY`
  (`socks5h://host.docker.internal:1080` или `http://host.docker.internal:3128`)
  и перезапусти контейнер. В Docker `127.0.0.1` — это сам контейнер, поэтому
  прокси на хосте указывается через `host.docker.internal` (уже добавлен в compose).
  Бот уже предпочитает IPv4 (`dns.setDefaultResultOrder('ipv4first')`), так что
  «мёртвый» IPv6 в Docker не должен мешать.
- `409: Conflict` — с этим токеном уже работает другой процесс/контейнер.
  Проверь `docker ps` (и не запускай одновременно `npm run dev` и Docker).
- Логи: `docker compose logs -f --tail=100`.
